## English

**PolyglotImportCSV 3.2.0** chooses the read block and the write batch by itself,
and its graphical interface is now in English.

### Changes

- **The read block is chosen for each run.** Without `--chunk-size`, the tool
  takes the block that reads the largest source whole, unless the predicted peak
  memory would exceed a quarter of the free memory; then it takes the largest block
  that fits, from 16 to 256 MB. The chosen size and the reason are printed and
  recorded in the session log, for example
  `Read block: 96 MB (auto: largest source read whole (96.1 MB); 1033 MB free)`.
  The rule comes from an exploratory campaign (`benchmarks/v4-explore`): reading the
  largest source whole was faster than every block of 16 to 64 MB (these took 14% and 21% longer on average in the two passes run under stable conditions), and the
  batch size made no difference beyond noise. `--chunk-size` still sets the block
  by hand.
- **The write batch is 2048 rows by default.** `--batch-size` goes from 512 to 8192
  rows (it was 1024 to 8192 in 3.0.0).
- **The graphical interface is in English**, like the messages of the command line.
  The card of input files is now "CSV files (`--source`)", and the "Check DBMSs"
  button checks the target DBMSs.
- **The interface has no block or batch controls.** The command it builds leaves
  `--chunk-size` and `--batch-size` out, so the command line chooses them.
- **Benchmark campaigns** (`scripts/run_benchmarks.py`) have a `--batch-sizes` axis
  and record the free memory at the start of each run (`free_memory_mb`). The
  default `--chunk-sizes auto` resolves the automatic block once per volume and
  mode when the matrix starts and saves it in the metadata, so `--resume` reuses it.
  The metadata also record the measured commit (`git_commit`).

### About 3.1.0 and 3.1.1

The tags `v3.1.0` and `v3.1.1` exist, but their releases were not published: the
tests of the release workflow failed. What they changed (a new icon, sliders for
the block and the batch, and the block and batch limits) is part of this release;
the sliders were later removed in favour of the automatic sizes.

## Português (BR)

A **PolyglotImportCSV 3.2.0** escolhe sozinha o bloco de leitura e o lote de
gravação, e a interface gráfica agora está em inglês.

### Mudanças

- **O bloco de leitura é escolhido a cada execução.** Sem `--chunk-size`, a
  ferramenta usa o bloco que lê a maior fonte inteira, a menos que o pico de memória
  previsto passe de um quarto da memória livre; nesse caso, usa o maior bloco que
  cabe, de 16 a 256 MB. O tamanho escolhido e o motivo aparecem na saída e no log da
  sessão, por exemplo
  `Read block: 96 MB (auto: largest source read whole (96.1 MB); 1033 MB free)`.
  A regra vem de uma campanha exploratória (`benchmarks/v4-explore`): ler a maior
  fonte inteira foi mais rápido que todos os blocos de 16 a 64 MB (que levaram, em média, 14% e 21% a mais nas duas passadas feitas em condições estáveis), e o tamanho do
  lote não fez diferença além do ruído. `--chunk-size` continua definindo o bloco à
  mão.
- **O lote de gravação tem 2048 linhas por padrão.** `--batch-size` vai de 512 a 8192
  linhas (na 3.0.0, ia de 1024 a 8192).
- **A interface gráfica está em inglês**, como as mensagens da linha de comando. O
  cartão dos arquivos de entrada agora se chama "CSV files (`--source`)", e o botão
  "Check DBMSs" verifica os SGBDs de destino.
- **A interface não tem controles de bloco nem de lote.** O comando que ela monta
  não inclui `--chunk-size` nem `--batch-size`, e a linha de comando os escolhe.
- **Campanhas de desempenho** (`scripts/run_benchmarks.py`) ganham o eixo
  `--batch-sizes` e registram a memória livre no início de cada execução
  (`free_memory_mb`). O padrão `--chunk-sizes auto` resolve o bloco automático uma
  vez por volume e modo, no início da matriz, e o salva nos metadados, para que o
  `--resume` o reaproveite. Os metadados também registram o commit medido
  (`git_commit`).

### Sobre a 3.1.0 e a 3.1.1

As tags `v3.1.0` e `v3.1.1` existem, mas as releases não foram publicadas: os testes
do fluxo de release falharam. O que elas mudaram (um ícone novo, *sliders* para o
bloco e o lote e os limites do bloco e do lote) faz parte desta release; os *sliders*
depois saíram, em favor dos tamanhos automáticos.
