## English

**PolyglotImportCSV 3.0.0** makes streaming the only way to import and checks
the data before it writes anything. It changes the command line in an
incompatible way.

### Breaking changes

Update your scripts and campaign commands for these:

- **`--execution` was removed.** Every import streams: each source is read in
  chunks and never loaded whole. Remove `--execution stream` and
  `--execution materialize` from your scripts; a command that still passes the
  option is rejected.
- **`--create-schema` and `--no-create-schema` were removed.** Before writing,
  the tool now always prepares each DBMS: it creates the Cassandra keyspace, the
  PostgreSQL and Cassandra tables and the Neo4j uniqueness constraints that do not
  exist yet, and reuses the ones that do; it drops the PostgreSQL foreign keys of
  the mapping before writing and adds them back at the end. MongoDB and Redis need
  nothing created. The option never did what its name said: in streaming, the
  default of every earlier release, `CREATE TABLE IF NOT EXISTS` ran in PostgreSQL
  and Cassandra, and the Neo4j constraints were created, with or without it.
  `--no-create-schema` skipped only two things: creating the Cassandra keyspace
  (the write failed if it did not exist yet) and dropping the PostgreSQL foreign
  keys before writing, so a new load over the foreign keys of an earlier one could
  violate a foreign key in the middle of the write. Only the whole-file load
  (`--execution materialize`) honored the option. Remove it from your scripts; a
  command that still passes it is rejected.
- **`target_suffix` of an `each` filter is now a template.** It must hold
  `{value}` exactly once, with only letters, digits and `_` around it, and
  `{value}` is replaced by the value of each part: `"target_suffix": "state_{value}"`
  on the entity `orders` writes `orders_state_SP`, `orders_state_RJ` and so on.
  Before, the text was used as it was, so every part got the same name. A
  configuration whose `target_suffix` lacks `{value}` is refused by the JSON Schema
  check, with exit code 1.
- **`--chunk-size` and `--batch-size` are new.** `--chunk-size MB` is the memory
  budget of each read chunk (default 8, from 8 to 256). `--batch-size N` is the
  number of rows per write batch (default 1024, from 1024 to 8192), capped at the
  rows of one read chunk. A value out of range is a usage error.
- **Benchmark campaigns** have `--chunk-sizes` (MB, comma-separated, default `8`)
  in place of `--executions`, in `scripts/run_benchmarks.py` and in
  `scripts/benchmark_tracemalloc_ab.py`. The consolidated `benchmark_results.csv`
  has a `chunk_mb` column in place of `execution`. A results file with the old
  header is refused with exit code 2 before anything is measured, so pass `--out`
  with another folder.
- **Metrics** are recorded per phase `infer`, `validate` and `write` (one per
  DBMS), in the `--benchmark` output and in the results CSV. The earlier `read`,
  `filter` and `map` phases are gone.
- **The DBMS column is named `dbms`**, in place of its earlier name, in the
  metrics table, in the `--benchmark` output, in `benchmark_results.csv` and in the
  records of `benchmark_run_*.json`. The campaigns under `benchmarks/` were
  converted. A results file with the old header is refused with exit code 2, as
  above.

### Changes

What else is new:

- **The data are checked before anything is written.** An import reads the data
  three times: an inference read, which infers the type of each column over the
  whole file; a validation read, which runs every row through the same code as the
  write, with the writes replaced by checks; and the write read. Any problem stops
  the run with exit code 1 before anything is written: a value that does not convert
  to the type of its column, a value the declared `db_type` would refuse, an empty
  key, a dangling reference and, in a combined CSV, a source that never appears in
  the origin column. Each kind of problem is reported with a count and up to 5
  examples, with file, line, column and value.
- **`--dry-run` now reads the data.** It runs the header check, the inference read
  and the validation read, prints the row counts per entity and connects to no DBMS.
- **The GUI** lost the "Execução" and "Criar esquema" controls and gained two
  fields, "Bloco em MB (`--chunk-size`)" and "Lote (`--batch-size`)".
- **JSON Schema errors name the field** they refuse, as a JSON path:
  `Invalid import configuration JSON at $.sources.stock: ...`.
- **The e-commerce example** has a new MongoDB collection, `orders`, split by the
  buyer's state with `each` and `"target_suffix": "state_{value}"`:
  `orders_state_CA`, `orders_state_SP` and so on.

## Português (BR)

O **PolyglotImportCSV 3.0.0** faz da transmissão em blocos a única forma de
importar e confere os dados antes de gravar qualquer coisa. Ele muda
a linha de comando de forma incompatível.

### Mudanças incompatíveis

Atualize seus scripts e comandos de campanha para estas:

- **A opção `--execution` foi removida.** Toda importação transmite: cada fonte é
  lida em blocos e nunca carregada inteira. Retire `--execution stream` e
  `--execution materialize` dos seus scripts; um comando que ainda passe a opção é
  recusado.
- **As opções `--create-schema` e `--no-create-schema` foram removidas.** Antes de
  gravar, a ferramenta agora sempre prepara cada SGBD: cria o *keyspace* do
  Cassandra, as tabelas do PostgreSQL e do Cassandra e as restrições de unicidade do
  Neo4j que ainda não existirem, e reaproveita as que existem; remove as chaves
  estrangeiras do mapeamento no PostgreSQL antes de gravar e as recria no fim.
  MongoDB e Redis não precisam de nada criado. A opção nunca fez o que o nome dizia:
  na transmissão em blocos, o padrão de todas as versões anteriores, o
  `CREATE TABLE IF NOT EXISTS` rodava no PostgreSQL e no Cassandra, e as restrições
  do Neo4j eram criadas, com ou sem ela. A `--no-create-schema` só deixava de fazer
  duas coisas: criar o *keyspace* do Cassandra (a gravação falhava se ele ainda não
  existisse) e remover as chaves estrangeiras do PostgreSQL antes de gravar. Por isso uma nova
  carga sobre as chaves estrangeiras de uma carga anterior podia violar uma chave
  estrangeira no meio da gravação. Só a carga integral (`--execution materialize`)
  respeitava a opção. Retire-a dos seus scripts; um comando que ainda a passe é
  recusado.
- **O `target_suffix` de um filtro `each` agora é um modelo.** Ele deve conter
  `{value}` exatamente uma vez, só com letras, dígitos e `_` em volta, e `{value}` é
  trocado pelo valor de cada parte: `"target_suffix": "state_{value}"` na entidade
  `orders` grava `orders_state_SP`, `orders_state_RJ` e assim por diante. Antes, o
  texto era usado como estava, e todas as partes recebiam o mesmo nome. Uma
  configuração cujo `target_suffix` não tenha `{value}` é recusada pela conferência
  do JSON Schema, com código de saída 1.
- **`--chunk-size` e `--batch-size` são novas.** `--chunk-size MB` é a memória
  reservada a cada bloco de leitura (padrão 8, de 8 a 256). `--batch-size N` é o
  número de linhas por lote de gravação (padrão 1024, de 1024 a 8192), limitado às
  linhas de um bloco de leitura. Um valor fora da faixa é erro de uso.
- **As campanhas de benchmark** têm `--chunk-sizes` (MB, separados por vírgula,
  padrão `8`) no lugar de `--executions`, no `scripts/run_benchmarks.py` e no
  `scripts/benchmark_tracemalloc_ab.py`. O `benchmark_results.csv` consolidado tem
  uma coluna `chunk_mb` no lugar de `execution`. Um arquivo de resultados com o
  cabeçalho antigo é recusado com código de saída 2 antes de medir qualquer coisa;
  para campanhas novas, passe `--out` com outra pasta.
- **As métricas** são gravadas por fase `infer`, `validate` e `write` (uma por
  SGBD), na saída de `--benchmark` e no CSV de resultados. As fases anteriores
  `read`, `filter` e `map` deixaram de existir.
- **A coluna do SGBD chama-se `dbms`**, no lugar do nome anterior, na tabela de
  métricas, na saída de `--benchmark`, no `benchmark_results.csv` e nos registros
  dos `benchmark_run_*.json`. As campanhas em `benchmarks/` foram convertidas. Um
  arquivo de resultados com o cabeçalho antigo é recusado com código de saída 2,
  como acima.

### Mudanças

O que mais há de novo:

- **Os dados são conferidos antes de gravar qualquer coisa.** Uma importação lê os
  dados três vezes: uma leitura de inferência, que infere o tipo de cada coluna sobre
  o arquivo inteiro; uma leitura de validação, que passa cada linha pelo mesmo código
  da gravação, com a escrita trocada por conferências; e a leitura de gravação.
  Qualquer problema interrompe a execução com código 1 antes de gravar: valor que não
  converte para o tipo da coluna, valor que o `db_type` declarado recusaria, chave
  vazia, referência pendente e, em um CSV combinado, fonte que nunca aparece na
  coluna de origem. Cada tipo de problema é reportado com a contagem e até 5
  exemplos, com arquivo, linha, coluna e valor.
- **O `--dry-run` agora lê os dados.** Ele faz a conferência dos cabeçalhos, a leitura
  de inferência e a de validação, mostra a contagem de linhas por entidade e não
  conecta a nenhum SGBD.
- **A interface gráfica** perdeu os controles "Execução" e "Criar esquema" e ganhou
  dois campos, "Bloco em MB (`--chunk-size`)" e "Lote (`--batch-size`)".
- **Os erros de JSON Schema citam o campo** que recusam, como um caminho JSON:
  `Invalid import configuration JSON at $.sources.stock: ...`.
- **O cenário de exemplo** tem uma coleção nova no MongoDB, `orders`, dividida pelo
  estado do comprador com `each` e `"target_suffix": "state_{value}"`:
  `orders_state_CA`, `orders_state_SP` e assim por diante.
