## English

**PolyglotImportCSV 3.0.0** makes streaming the only way to import and checks
the data before it writes anything. It changes the command line in an
incompatible way.

### Breaking changes

Update your scripts and campaign commands for these:

- **`--execution` was removed.** Every import streams: each source is read in
  chunks and never loaded whole. Remove `--execution stream` and
  `--execution materialize` from your scripts; a command that still passes the
  option is rejected.
- **`--chunk-size` and `--batch-size` are new.** `--chunk-size MB` is the memory
  budget of each read chunk (default 8, from 8 to 256). `--batch-size N` is the
  number of rows per write batch (default 1024, from 1024 to 8192), capped at the
  rows of one read chunk. A value out of range is a usage error.
- **Benchmark campaigns** have `--chunk-sizes` (MB, comma-separated, default `8`)
  in place of `--executions`, in `scripts/run_benchmarks.py` and in
  `scripts/benchmark_tracemalloc_ab.py`. The consolidated `benchmark_results.csv`
  has a `chunk_mb` column in place of `execution`. A results file with the old
  header is refused with exit code 2 before anything is measured, so pass `--out`
  with another folder.
- **Metrics** are recorded per phase `infer`, `validate` and `write` (one per
  DBMS), in the `--benchmark` output and in the results CSV. The earlier `read`,
  `filter` and `map` phases are gone.

### Changes

What else is new:

- **The data are checked before anything is written.** An import reads the data
  three times: an inference read, which infers the type of each column over the
  whole file; a validation read, which runs every row through the same code as the
  write, with the writes replaced by checks; and the write read. Any problem stops
  the run with exit code 1 before anything is written: a value that does not convert
  to the type of its column, a value the declared `db_type` would refuse, an empty
  key, a dangling reference and, in a combined CSV, a source that never appears in
  the origin column. Each kind of problem is reported with a count and up to 5
  examples, with file, line, column and value.
- **`--dry-run` now reads the data.** It runs the header check, the inference read
  and the validation read, prints the row counts per entity and connects to no DBMS.
- **The GUI** lost the "Execução" control and gained two fields, "Bloco em MB
  (`--chunk-size`)" and "Lote (`--batch-size`)".

## Português (BR)

O **PolyglotImportCSV 3.0.0** faz da transmissão em blocos a única forma de
importar e confere os dados antes de gravar qualquer coisa. Ele muda
a linha de comando de forma incompatível.

### Mudanças incompatíveis

Atualize seus scripts e comandos de campanha para estas:

- **A opção `--execution` foi removida.** Toda importação transmite: cada fonte é
  lida em blocos e nunca carregada inteira. Retire `--execution stream` e
  `--execution materialize` dos seus scripts; um comando que ainda passe a opção é
  recusado.
- **`--chunk-size` e `--batch-size` são novas.** `--chunk-size MB` é a memória
  reservada a cada bloco de leitura (padrão 8, de 8 a 256). `--batch-size N` é o
  número de linhas por lote de gravação (padrão 1024, de 1024 a 8192), limitado às
  linhas de um bloco de leitura. Um valor fora da faixa é erro de uso.
- **As campanhas de benchmark** têm `--chunk-sizes` (MB, separados por vírgula,
  padrão `8`) no lugar de `--executions`, no `scripts/run_benchmarks.py` e no
  `scripts/benchmark_tracemalloc_ab.py`. O `benchmark_results.csv` consolidado tem
  uma coluna `chunk_mb` no lugar de `execution`. Um arquivo de resultados com o
  cabeçalho antigo é recusado com código de saída 2 antes de medir qualquer coisa;
  para campanhas novas, passe `--out` com outra pasta.
- **As métricas** são gravadas por fase `infer`, `validate` e `write` (uma por
  SGBD), na saída de `--benchmark` e no CSV de resultados. As fases anteriores
  `read`, `filter` e `map` deixaram de existir.

### Mudanças

O que mais há de novo:

- **Os dados são conferidos antes de gravar qualquer coisa.** Uma importação lê os
  dados três vezes: uma leitura de inferência, que infere o tipo de cada coluna sobre
  o arquivo inteiro; uma leitura de validação, que passa cada linha pelo mesmo código
  da gravação, com a escrita trocada por conferências; e a leitura de gravação.
  Qualquer problema interrompe a execução com código 1 antes de gravar: valor que não
  converte para o tipo da coluna, valor que o `db_type` declarado recusaria, chave
  vazia, referência pendente e, em um CSV combinado, fonte que nunca aparece na
  coluna de origem. Cada tipo de problema é reportado com a contagem e até 5
  exemplos, com arquivo, linha, coluna e valor.
- **O `--dry-run` agora lê os dados.** Ele faz a conferência dos cabeçalhos, a leitura
  de inferência e a de validação, mostra a contagem de linhas por entidade e não
  conecta a nenhum SGBD.
- **A interface gráfica** perdeu o controle "Execução" e ganhou dois campos, "Bloco
  em MB (`--chunk-size`)" e "Lote (`--batch-size`)".
