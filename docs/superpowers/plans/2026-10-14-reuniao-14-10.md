# Reunião de 14/10 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the `naive` write strategy and the `--strategy` option from the tool, document the CSV header requirement, answer the examining board's multi-source × combined question in the report, and ship report v2.4 plus releases v1.1.0 and v2.0.0.

**Architecture:** The strategy parameter is threaded top-down (GUI → benchmark runner → CLI → runner → importers → casting); it is removed in that order so the suite stays green after every task (each layer stops passing the argument before the layer below stops accepting it). The report is edited with exact LaTeX replacements; numbers come only from the August campaigns already in `benchmarks/` and from the deterministic files in `data/benchmark/generated/`.

**Tech Stack:** Python 3.14, click, pandas, PySide6, pytest (+ pytest-qt), LaTeX (abnTeX2, latexmk, pgfplots), git + GitHub Actions (release on tags `v*`), `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-14-reuniao-14-10-design.md`

## Review Focus

1. A user script still calling `--strategy optimized` → the CLI exits with code 2 and click's "No such option: --strategy", it does not run anything (test in Task 3).
2. Resuming a benchmark checkpoint written before this change that contains `naive` runs → refused with a clear `ValueError` naming the removed strategy, instead of silently merging naive and batch timings into one median (test in Task 2).
3. Running the benchmark into `benchmarks/` whose `benchmark_results.csv` still has the old header with `strategy` → `ValueError` "CSV header mismatch" and the provenance file is left byte-for-byte unchanged (test in Task 2).

5. The GUI command panel, at defaults and in every combination, never shows `--strategy` (tests in Task 1).

**Language / Idioma / Língua:** [English](#english) · [Português (BR)](#português-br)

## English

**PolyglotImportCSV 2.0.0** has a single write strategy and a stricter
connection file.

### Breaking changes

- **`--strategy` was removed.** The tool always converts types column by column
  and writes in batches. Remove `--strategy optimized` from your scripts; a
  command that still passes it is rejected. The row-at-a-time strategy
  (`naive`) remains available in version 1.1.0.
- **`connection` is required** in every DBMS block of `dbms_config.json`. A
  block without it is rejected when the file is validated.
- **Benchmark results** no longer have a `strategy` column. Move an old
  `benchmark_results.csv` aside before appending new runs to its folder.

| `polyglotimportcsv-gui-v2.0.0-linux-x64.zip` | GUI for Linux |

Every package carries the e-commerce example, `docker-compose.yml` and a
